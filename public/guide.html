0이 프로젝트에서 나는

내가 기능의 주인

무엇을 만들지, 어떻게 보일지는 내가 정합니다. 9개 기능 목록은 정답이 아니라 아이디어 씨앗이에요. 새 기능을 제안하고 바로 시작해도 됩니다.

AI는 내 조수

코드는 AI가 씁니다. 나는 원하는 것을 설명하고, 결과를 확인하고, 더 낫게 만들 방향을 정합니다.

대표는 조언자

대표는 지시하는 사람이 아니라 막혔을 때 같이 고민하는 사람이에요. 검토 의견도 "이건 어떻게 생각해?"로 드려요.

지켜야 할 울타리는 3개뿐

내 폴더 안에서내 기능 폴더 app/내기능/ 안은 자유. 그 밖의 파일은 대표에게 요청합니다.
비밀은 넣지 않기비밀번호·API 키·실제 학생 개인정보를 코드에 넣지 않습니다.
10분 규칙10분 넘게 막히면 혼자 버티지 말고 도움을 요청합니다. (방법)

이 3가지는 자동 검사도 함께 지켜 줍니다. 실수해도 앱이 망가지지 않으니 마음껏 시도해 보세요.

1시작하기 (5분)

처음 한 번 · 컴퓨터실이어도 설치 없음

GitHub의 Codespaces는 인터넷 속 내 개발용 컴퓨터예요. 컴퓨터실 PC를 껐다 켜도 내 작업은 그대로 남아 있습니다.

  1. GitHub에 로그인하고 저장소 열기
    github.com/Unjung-app/unjung-app
  2. 초록색 Code → Codespaces 탭 → Create codespace on main
    처음엔 준비에 2~3분 걸립니다. 기다리는 동안 3. AI와 만들기를 읽어 두세요.
    브라우저 안에 VS Code가 열리고, 아래쪽에 앱 실행 (npm run dev) 터미널이 저절로 켜지고, 오른쪽에 앱 미리보기가 나타납니다.
    미리보기가 안 보이면 아래쪽 포트(PORTS) 탭 → 3000번 줄의 🌐 아이콘을 누르면 새 탭으로 열립니다. 휴대폰 크기로 보려면 그 탭에서 F12 → 휴대폰 아이콘.
  3. 명령을 입력할 터미널 하나 더 열기
    터미널 패널 오른쪽 위 + 버튼을 누릅니다. 앞으로 명령은 모두 이 새 터미널에 입력합니다. "앱 실행" 터미널은 닫지 마세요.
내 노트북에 설치해서 하고 싶다면 (선택)

Git, Node.js(LTS), VS Code를 설치한 뒤, 명령 프롬프트(맥은 터미널)에서:

git clone https://github.com/Unjung-app/unjung-app.git
cd unjung-app
code .

VS Code가 열리면 앱이 자동으로 켜집니다(안 켜지면 터미널에서 npm run dev). 앱 주소는 localhost:3000. 이후 과정은 Codespaces와 같습니다.

2내 기능 고르기

매 회차 시작할 때
npm run work
  • 영문 이름: 소문자로 (예: howon). 다음부터는 Enter만 누르면 됩니다.
  • 번호: 이미 있는 기능을 고르거나, 0번을 골라 내 아이디어로 새 기능을 만듭니다.
준비 끝!과 함께 내 폴더(app/○○/)가 표시됩니다. 미리보기에서 주소 뒤에 /○○를 붙이면 내 화면이에요.

무엇을 고를까?

  • 아이디어 상태의 기능을 맡으면, 그 기능의 "만든 사람"에 내 이름이 올라갑니다.
  • 만드는 중인 기능에 합류해도 됩니다. 같은 기능을 함께 만들 땐 먼저 만든 사람과 이야기해 두세요.
  • 새 기능(0번): 기능 이름, 한 줄 설명, 주소로 쓸 영어 이름(예: music-request), 아이콘(이모지)을 물어봅니다. 홈 화면에 바로 나타나요.
다른 사람도 볼 수 있게 아이디어를 올려 두면 좋아요: GitHub 저장소 → Issues → New issue → 💡 기능 아이디어. 허락을 기다릴 필요는 없습니다.

3AI와 만들기

만들고 → 확인하고 → 다시 요청하기를 반복
  1. AI에게 보낼 내용 준비
    npm run ai
    ai-context.md 탭이 열립니다. 그 탭을 클릭하고 Ctrl+A → Ctrl+C. (프로젝트 규칙 + 내 코드가 들어 있어요)
  2. AI 채팅(ChatGPT·Claude·Gemini 등)을 새로 열고 붙여넣기
    AI가 "준비됐어"라고 답합니다.
  3. 만들고 싶은 것을 이야기하기
    AI가 다시 질문하면 답해 주세요. 잘 모르겠으면 "가장 간단한 방식으로 해 줘"도 괜찮아요.
  4. AI가 준 코드를 파일에 넣기
    AI 답에 적힌 파일 경로(예: app/music-request/page.js)의 파일을 왼쪽 목록에서 열고 → Ctrl+A → Ctrl+V. 자동 저장됩니다.
    새 파일이 필요하면 내 폴더를 마우스 오른쪽 클릭 → 새 파일 → AI가 말한 이름.
  5. 미리보기에서 눌러 보고, 다음 요청하기
    같은 채팅에 이어서 요청하고 4~5번을 반복합니다. 채팅을 새로 시작할 땐 npm run ai부터 다시.

요청을 잘하는 3가지 원칙

  • 한 번에 하나씩. "급식 앱 다 만들어 줘"보다 "오늘 메뉴를 카드로 보여 줘" → "알레르기 표시 추가해 줘"처럼 작게 쌓아 가세요.
  • 화면을 묘사하기. 무엇이 보이고, 무엇을 누르면 어떻게 되는지 말하세요. 친구에게 설명하듯이.
  • 쓰는 사람을 떠올리기. 이 화면을 여는 친구가 제일 먼저 알고 싶은 게 뭘까? 그게 화면 맨 위에 와야 해요.
예) 신청곡 화면에 노래 제목과 가수를 입력하는 칸과 [신청] 버튼을 만들어 줘. 신청하면 아래 목록에 추가되게 해 줘. 데이터는 예시로 3곡 넣어 줘.
잘 안 될 때 AI에게 고쳐 달라고 하는 형식
[내가 한 것] 신청 버튼을 눌렀어. [기대한 것] 목록에 노래가 추가돼야 해. [실제로 일어난 것] 아무 반응이 없어. [에러 메시지] (빨간 글자를 전부 복사해서 붙여넣기. 없으면 "없음")

빨간 에러는 요약하지 말고 전부 복사하세요. 원인이 그 안에 있어요.

아이디어가 막혔을 때

AI에게 "정답 말고 질문으로 도와줘. 이 기능을 더 쓸모 있게 만들려면 뭘 생각해 봐야 할까?"라고 해 보세요. 친구 한 명에게 화면을 보여 주고 "뭐가 제일 불편해?"라고 묻는 것도 최고의 방법이에요.

4제출하기

작은 것이라도 완성될 때마다 (자주 할수록 좋아요)
  1. 저장하고 올리기
    npm run save
    무엇을 했는지 한 줄로 적고 Enter. 다른 사람들의 최신 작업도 자동으로 합쳐집니다.
    [완료] GitHub에 올림과 PR 주소가 나옵니다.
  2. PR 만들기 (처음 한 번)
    PR 주소를 Ctrl을 누른 채 클릭 → AI에게 "PR 설명 써줘"라고 해서 받은 글을 붙여넣기 → 초록색 Create pull request.
    한 번 만든 PR에는 이후 npm run save한 내용이 자동으로 추가됩니다. PR을 새로 만들 필요 없어요.
  3. 자동 검사와 의견 확인
    PR 아래 자동 검사가 초록 ✓이면 통과. 빨간 ✗이면 Details를 눌러 나온 글을 AI에게 보여 주세요. Vercel이 달아 주는 Preview 링크로 휴대폰에서도 볼 수 있어요. 대표나 친구가 의견을 남기면 같이 이야기하고, 합쳐지면(보라색 Merged) 1~2분 뒤 실제 앱에 나옵니다.

"다 만들었다!" 싶으면

AI에게 "feature.json의 status를 ready로 바꿔 줘"라고 하고 저장·제출하세요. 홈 화면에서 사용할 수 있어요로 올라갑니다.

5끝내기 · 이어 하기

끝낼 때

  • npm run save로 올려 두면 가장 안전해요. (Codespaces 안의 작업은 올리지 않아도 남아 있지만, 올려야 다른 사람도 볼 수 있어요)
  • 브라우저 탭을 닫으면 Codespace는 30분 뒤 저절로 멈춥니다.
  • 컴퓨터실이라면 GitHub와 AI 사이트에서 꼭 로그아웃하세요.

다음에 이어 할 때

  • github.com/codespaces에서 지난번 Codespace를 눌러 다시 엽니다. (새로 만들지 않아도 돼요)
  • 새 터미널에서 npm run work → Enter 두 번이면 지난 작업 그대로, 그동안 다른 사람이 만든 것까지 받아와서 이어집니다.
Codespaces는 개인 GitHub 계정마다 매달 무료 사용 시간이 있어요. 수업 시간 정도는 충분하지만, 다 쓰고 나면 그냥 멈출 뿐 돈이 나가지는 않습니다(결제 수단을 등록하지 않았다면).

!충돌이 나면

같은 파일의 같은 부분을 두 사람이 다르게 고치면 "충돌"이 납니다. 망가진 게 아니에요. 두 사람의 코드가 모두 파일 안에 남아 있고, 어떻게 합칠지만 정하면 됩니다.

  1. 자동으로 열린 conflict-help.md 탭 전체를 복사해서 AI에게 붙여넣기
    이 요청문에는 "두 사람의 기능을 모두 살려 줘"라는 규칙이 들어 있어요.
  2. AI가 준 파일 전체 코드로 그 파일을 통째로 바꾸기
  3. 미리보기에서 내 기능과 다른 사람 기능이 둘 다 되는지 확인
  4. npm run save
    <<<<<<< 같은 충돌 표시가 남아 있으면 저장이 멈추고 알려 줍니다.
AI가 "한쪽 코드를 지워야 한다"고 하면, 진행하기 전에 그 코드를 만든 사람이나 대표와 먼저 이야기하세요. PR 화면에 충돌 경고가 떠 있으면 대표도 병합 버튼을 누르지 않습니다.

?막혔을 때

아래 표에서 찾아보고, 없거나 10분이 넘으면 화면 글자를 전부 복사해서 단톡방에 보내거나 GitHub Issues → 🆘 도움 요청에 올리세요.

이런 일이 생기면이렇게 하세요
미리보기가 안 보임아래 포트(PORTS) 탭 → 3000번의 🌐 아이콘. 3000번이 없으면 "앱 실행" 터미널이 꺼진 것 → 새 터미널에서 npm run dev
"앱 실행" 터미널을 닫아 버림새 터미널에서 npm run dev (그 터미널은 앱 전용으로 두기)
코드를 바꿨는데 화면이 그대로미리보기 새로고침. 그래도 같으면 파일 탭 이름 옆 ● 확인(저장 안 됨) → Ctrl+S
화면 전체에 빨간 에러빨간 글자 전부 복사 → AI에게 "이 에러가 떠:" + 붙여넣기
404 화면주소 확인: 앱 주소 뒤에 /내폴더이름
홈 화면에 내 기능이 안 보임feature.json 형식이 깨졌을 수 있어요. "앱 실행" 터미널의 [주의] 글을 AI에게 보여 주기
[멈춤] 저장하지 않은 변경 파일이 … 있어먼저 npm run save → 다시 npm run work
[멈춤] 내 기능 브랜치가 아닙니다npm run work부터
Missing script터미널 위치가 다른 폴더. 새 터미널을 열어서 다시
Codespace가 "Stopped"github.com/codespaces 에서 다시 열기 (작업은 그대로 있어요)
PR의 Merge 버튼이 회색정상이에요. 대표의 확인을 기다립니다
하면 안 되는 것

AI가 알려 준 명령 중 --force, reset, rebase, git push가 들어간 것은 실행하지 말고 먼저 물어보세요. 저장·제출은 npm run save가 다 해 줍니다.
